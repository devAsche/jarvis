# 00 — プロジェクトの意図と背景

## ユーザーの目的（実際の発言・過去の相談から）

- Instagram ReelsのJARVIS風自律型秘書の**体験**を可能な限り再現したい。例: 人間の勤務開始前に仕事を整理し、朝9:30頃に声で報告、過去24hの異常検知、コミュニティの新規参加/投稿/質問、滞留タスクを提示、集中作業の時間を提案。リールの実装内部は不明であり、全自動性が実証されたわけではない。
- 目指す本質は「映画のUIを持つ実業務用のOS」。見栄えだけのデモにも、文字だけの業務ツールにも寄せない。音声主体と複数モニターの演出を考慮する。
- 使用環境: Windows、`C:\AI` を複数AI開発環境の共通土台にする。Google AI系契約＋ローカルAntigravity導入済み、ChatGPT Plus/Codex利用中。既存契約を優先し、新規課金API/サービスを無断契約しない。高推論の連続使用による利用制限を回避するため、狭いタスク割り・テスト・バトンパスを重視。
- ビジネス柱: (a) 米国向けShopifyペットの抜け毛掃除ニッチストア（ドロップシッピングで小規模検証）、(b) 歌い手/動画投稿/配信活動、(c) MIX/動画編集受注。発展形として他の自社事業も追加できるモジュラー設計。
- EC初期背景: ピンクのケース付き毛取りブラシと商品回転3Dヒーロー制作、CJ型番 `CJGY103503904DW` 等を検討。**これを現在販売中の商品・確定した仕入れ許諾とはみなさない。** 特許・商標・素材使用権・納期を確認するまで該当商品の自動販売操作を保留する。
- 個人事業の資金制約: 検証費用を少額に抑え、注文/広告支出/関税/返品と利益計算を重視。経営者として意思決定と失敗から学びたいので、AIは意思決定を隠して代行するのではなく「根拠を示して提案 → 承認 → 記録 → 振り返り」のループを作る。
- 関連構想: 目覚ましとTo-Do読み上げ、TickTick同期、SNSの運用補助、毎日の業務改善、将来的な顧客対応や発信の一部自動化。ただしX等のAPI権限/規約は個別に確認し、DM・いいね・フォローの無差別自動化をしない。

## 例示する理想体験（この仕様に落とす）

朝の起動 → JARVISが時間帯/スケジュール/重要イベント/保留タスクをローカル時刻で確認 → データの鮮度を示しながら要約 → 音声または画面で提示 → 重要度順でカードを並べる → 作業集中枠候補を提案（**カレンダー変更は許可制**）→ ユーザーが「詳細」「下書き作成」「承認」等を選択 → 実行履歴が残る。

将来: EC受注・利益率の異常、MIX問い合わせ・制作ステータス、未返信メール、予約、SNS反応を統合。定期実行とイベント駆動を組み合わせ、ユーザーが寝ている間にも安全な読み取り・準備作業だけを進める。スマホへの通知や音声通話は必要性を検証して後から追加。

## 仕事の分担

- **Antigravity**: 体験設計、UI実装/ブラウザQA、モックE2E、ブラウザーが必要なサイトの人間監督下操作、全体のスモールタスク実装。
- **Codex**: データモデル、イベント処理、APIアダプター、認可ポリシー、テスト、差分レビュー、難しい障害対応。
- **完成品のJARVIS**: 独立したWeb/バックエンド/DBで稼働するアプリ。開発用AntigravityとCodexを24時間自動稼働の商用ランタイムと混同しない。

## 強い除外条件

- 資金移動や重要な契約のAI独断実行なし。音声だけで高額処理を確定しない。
- 早期からすべてをマルチエージェント化しない。
- ChatGPTのコネクター接続状態を、自作PCアプリのOAuth権限がある根拠としない。
- 「AIが毎日勝手に改善・本番反映」は実装しない。改善案・試験用ブランチ・自動テストまでとし、本番反映前にレビュー。
- 「動画にそう映っていた」ことを実サービスの実現方法や機能保証と混同しない。
