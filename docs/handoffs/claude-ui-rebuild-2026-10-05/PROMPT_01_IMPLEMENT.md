## 機能の通し方

1. テキストまたはVoice Mockの入力→`POST /api/demo/runs`→実際の`taskRunId`→根拠のある報告→承認待ち→対象・金額・期限を確認できるデモ承認→監査表示→中央Presenceへの状態連動を維持してください。現在のAPIで足りない場合は、まず最小の変更案と影響を示してください。
2. `DEMO`/`MOCK`のバッジを常時読める場所に置き、`LIVE_VERIFIED`、`STALE`、`UNKNOWN`を混同しないでください。fixtureの数字を実績と書かず、根拠のない`THINKING`/`EXECUTING`、実タスクを装うモック音声を出さないでください。重複・順不同イベントで表示を逆行させないでください。
3. 承認は現行のローカルデモ処理だけ。二重送信、期限切れ、対象変更を拒否し、音声の「はい」で確定しないでください。外部の注文・メール・広告・金銭操作につなげないでください。
4. Graphics `auto/balanced/low/off`、`Core2DFallback`、GPU失敗、reduced motionを働かせてください。アニメーションは視認できるが本文・操作を妨げない強さにし、非表示タブとアンマウント後の描画・音声処理を片付けてください。性能に問題があれば装飾を減らしてください。
5. デスクトップと390px幅で朝の報告、事業概況、承認、入力が読めて操作できるようにしてください。キーボードフォーカス、Escape、モーダル、十分なコントラストとタップ領域を確認してください。
