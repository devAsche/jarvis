## 今回の目的

ユーザーは現在のUIを気に入っていません。既存Next.jsアプリの**UIを一から再設計するための、選べる実物に近い案**を作ってください。今は完成UIを本番ルートへ実装する段階ではありません。旧3カラム、旧CR003のObservatory/Foundry、青白いコア、以前のユーザーの好みをデザイン決定として固定しないでください。既存の業務・安全契約は維持します。

## 先に行う確認と保全

1. `git status --short`、branch/HEAD、未追跡ファイル、差分、他worktree、動作中プロセスを確認。ローカルの元環境ではCR001〜CR003実装が未コミット差分にもあったため、クラウド上のコミットに実装と本資料が入っているか実ファイルで確認してください。足りなければ停止し、欠損を報告してください。`reset`、`clean`、安易な`stash`、上書き、同一ファイルの同時編集をしないでください。保全方法と担当ファイル境界を短く宣言してください。
2. 現行UIを実ブラウザーでデスクトップと390px幅で撮影。通常、報告、承認、GPU失敗を可能な範囲で確認し、撮影条件を記録。もし起動しない場合は原因と未確認範囲を明示してください。ローカルdevとbuildの`.next`を同時に使わないでください。
3. コードから、朝の報告→デモrun→出典付き表示→承認待ち→デモ承認→監査イベント、音声モック、`taskRunId`連動、GPU fallback、キーボード操作の実態を確認。画面の言葉がデモを実運用と誤認させる箇所、情報の優先順位、視線移動、可読性、動きの負荷を指摘してください。

## 調査と提案

4. 現在アクセスできる公式デザインサイトや優れた実在UIを少数調査し、閲覧日・URL・実際に見た要素を残してください。`historical/RESEARCH_LOG.md`は履歴として読めますが、今回の閲覧証拠に流用しないでください。各参照について「観察」「抽象化」「今回使わない点」を分け、特定ブランドの画面・商標・映画表現をコピーしないでください。アクセスできないサイトは未確認と書いてください。
5. 画面全体のレイアウト、情報階層、配色、書体、中央Presenceの造形・動きが**明確に異なる2〜3案**を提案してください。雰囲気の言葉だけでなく、業務の重要操作がどこにあるかを示してください。旧3カラムを維持する必要はありません。Canvasは中央の表現だけ、業務テキストはDOM、WebGL失敗時も承認と数値は表示する方針は守ってください。
6. 可能なら各案を独立したプレビュールートか別フォルダーの軽量プロトタイプとして作り、画面全体とコアのデスクトップ/390pxキャプチャを用意してください。本番ルートを切り替えず、現行のAPI・store・fixtureを破壊しないでください。軽い試作用コードは許可します。重い依存追加や全体リファクタは行わないでください。
7. 各案について、良い点、欠点、実装工数の相対比較、業務の誤認リスク、描画負荷、狭幅対応、既存動作の維持方法を記録してください。ユーザーが選べるようにおすすめを一つ挙げてもよいですが、選択を代行しないでください。
