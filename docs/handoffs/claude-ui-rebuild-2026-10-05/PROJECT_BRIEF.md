# JARVIS Business OS UI再制作ブリーフ

## 依頼の意味

ユーザーは現在のUIを気に入っておらず、Claude Codeに画面を一から設計・制作してほしい。**既存のビジネスOSを新しいレポジトリで作り直す依頼ではない。** 同じNext.jsアプリの表示・画面構成・操作導線を大胆に再設計する。旧3カラム、旧A/B案、青い観測コア、カードの浮遊は参考資料であり、採用を強制しない。

見た目の確定条件はまだない。Claude Codeは現行画面と参考資料を監査し、異なる複数案を実画面に近い形で提示してユーザーの選択を待つ。その後、選択された方向だけを本番ルートに実装する。新しいデザインであっても、サンプル注文を本物の注文に見せる演出は不可。

## 製品の役割

利用者は当面1人。朝の業務状況、事業別の数字、根拠のあるブリーフ、人が判断する承認対象、状態と履歴を一画面から把握したい。将来は実データを安全に読み取る構想があるが、**現在はローカルDEMO**。UIは「何が起きたか」「出典は何か」「今、人が判断することは何か」「その判断の効果は何か」を短時間で読めることが重要。

現在のデモ素材は、注文額の例¥4,900、配送費見積¥900→提示¥1,550、差額¥650、MIX問い合わせ2件、予定1件、模擬承認1件。金額はfixture由来で、売上実績ではない。

## 作り直しで改善したいこと

1. まず業務上の判断と根拠が分かり、装飾や開発用語が読解を妨げないこと。
2. 中央のPresenceは人格や実行中を偽装せず、真の`taskRunId`や音声モック状態に対応すること。動きは見えるが、読みにくさやGPU過負荷を招かないこと。
3. 日本語の本文・数値・ラベルを十分な大きさで表示すること。ALL CAPS、細字、広い字間、同じ形のカードの連続を避けること。
4. デスクトップと390px幅で、承認、朝の報告、コマンド入力に迷わず届くこと。
5. 画面の雰囲気はClaude Codeが新たに提案する。旧スクリーンショットに似せることを目標にしない。参考元のブランド、ロゴ、映画意匠をコピーしない。

## デザインの自由度と固定点

自由: レイアウト、情報階層、色、書体の組合せ、余白、カード/レール構成、ナビゲーション、コアの造形、軽い動き。3カラムを維持する義務はない。

固定: 現行のNext.js/Reactアプリ内で動作し、意味のある業務テキスト、字幕、承認、金額、操作はDOMに残す。中央だけR3F Canvasを使用し、WebGL不具合・描画オフ・reduced motionでは2D fallbackを示す。Canvasの失敗で承認や数字を消さない。既存APIと契約は維持し、変える必要がある場合は理由と影響を明示してユーザー判断へ回す。

## デザイン調査の扱い

[historical/RESEARCH_LOG.md](historical/RESEARCH_LOG.md)には2026-09-28時点のLinear、Raycast、Vercel Geist、Jarvis Instituteの観察がある。これは履歴であり、現在のサイトや今回の好みを保証しない。Claude Codeは閲覧可能な公式サイトや実在UIを改めて確認し、「観察」「抽象化」「今回使わない点」を記録する。閲覧不可なら未確認と書く。旧A/B案を名前だけ変えて再提出しない。

## 成功の判断

ユーザーが選んだ案が、実ブラウザーのデスクトップとスマホで、ビジュアル・読解・操作の三点で現行画面より明確に良いこと。機能テスト合格とユーザーの見た目の承認を分けて報告する。
