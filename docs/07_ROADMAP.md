# 07 — 段階開発 / DoD / 受入条件

## M0: 共通リポジトリと検証基盤（最初のセッション）

- [ ] Git初期化と共通`AGENTS.md`が両開発環境で参照されることを確認。
- [ ] Node/npm/Git/ブラウザーのバージョンを報告。追加有料導入なし。
- [ ] Next.js/TypeScriptフロント、最小バックエンド、テスト/リント/フォーマットを公式対応バージョンで初期化。外部APIに依存せず起動。
- [ ] `docs/05_DATA_AND_API.md`を契約基準にモックイベント・briefを型で表現。
- [ ] `prototype/index.html`を参照してデザインシステムの最小設計。
- [ ] 動くトップページと開発/テスト手順をREADMEに追記。スクリーンショット1枚以上。

**DoD**: ローカルの起動、型チェック、テスト、lintが実行でき、実行結果/失敗を報告。`README`のコマンドはコピペ可能。実課金0。

## M1: 見た目と縦切りの完成

- [ ] PRESENCE / BRIEFING / DASHBOARD / APPROVAL / SYSTEMを画面として実装。暗い青のオリジナルUIと中央コアは初期からReact Three Fiber (R3F) 先行（CSS/SVGは2D fallbackとして保持）。VoiceSessionController + MockVoiceAdapterによるゼロ課金音声状態連携基盤を早期導入。
- [ ] モック `shopify order` と `MIX lead` を挿入 → 左フィードと右ステータス → 朝ブリーフ → 承認カードが更新される。
- [ ] approvalを承認/差し戻ししても「外部実行なし」を保証し監査ログへ記録。
- [ ] 1440×900と390×844（可能なら1920×1080）の実ブラウザスクショ、低モーション、キーボード操作。
- [ ] 古いデータ/未接続/故障の視覚状態がデモに存在。

**DoD**: 「朝の要約 → 根拠確認 → 案件選択 → 承認デモ → 監査確認」を、初見の利用者がドキュメントと共に手動再現可能。数字がすべてDEMOと明示。品質ゲートを通ったスクショを保存。

## M2: 読み取り専用の実データ

- [ ] 機密を漏らさずユーザーが認証できる仕組み。UIとAPIの認証を分離しない。
- [ ] 単一サービスから開始（有用度からShopifyを候補）。まず読み取りだけ。
- [ ] 署名検証/再試行/重複イベントのテスト。last_sync/stale表示。
- [ ] DB/バックアップと最小運用通知（失敗時の確認先）。数値の既知/未確認区別。

**DoD**: 1サービスの本物の読み取りデータが安全に表示され、同期停止/期限切れ/重複/障害にも安全側で動く。次の連携に進む前にユーザー確認。

## M3: 下書き・承認付き実行

- [ ] MIX返信下書き、商品改善提案、日次振り返りと改善仮説を作成。
- [ ] 操作の種類/金額/対象/TTLを固定したサーバー承認。監査と緊急停止、二重実行防止。
- [ ] まずテストアカウント、次にユーザー指定の実アカウントで**一度だけ**承認付き試験。

**DoD**: 機密/越権/二重操作/失敗再試行を含む負のテスト合格。無承認で副作用を起こせないことを証明。

## M4: 音声・常時稼働・複数事業

- [ ] テキストと共存する音声UI、オプショナル通話（費用とOS制約確認）。
- [ ] 予算上限内でクラウドworker/スケジューラー/監視を設計、PC電源OFF時を検証。
- [ ] UXが保てる場合のみ3Dの実装強化、マルチモニタとモバイル通知。
- [ ] 統合事業指標と改善仮説を毎日提示。自律的な本番コード反映は別承認。

**DoD**: 明示した費用内で連続稼働・失敗時の再開・安全停止・音声なし代替が実測確認できる。
