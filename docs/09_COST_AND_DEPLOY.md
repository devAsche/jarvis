# 09 — 低コスト運用・モデル選択・インフラ段階

ユーザーは既存契約（ChatGPT Plus、Google AI系、Grok）を優先し、新規APIや月額を自動で増やしたくない。**開発用のAntigravity/Codexのサブスクリプション枠と、自作JARVISから呼ぶ外部推論APIは別物**。無料枠/利用枠は時期や契約で変動するため数値を固定しない。

## フェーズごとの原則

- M0/M1: 完全mockと決定的ロジックを優先。外部モデル/クラウド/有料通話/DBは必須にしない。CPU上の静的UIは`prototype`を起点にする。
- M2: 事業価値が実証された1件のread-only APIだけ連携。低頻度ポーリング/WebhookとキャッシュでAPI呼出しを抑制。
- M3: 高価なモデルは不確実性が高い要約・難しい分析にだけ。定型的な判定・集計・メール振り分けはルールベースを優先。日次・週次単位の利用上限と即停止スイッチ。
- M4: 電話をかける機能は通話料金/常時稼働/認証を含め見積もり後に判断。クラウド利用の概算値もデプロイ先選定時に実価格で検証。

## 予算インストルメンテーション

各agent_runの推定料金、API成功/失敗/再試行数、provider別消費、週/月累積、超過による停止を計測。開発者が料金上限を設定してから課金機能を有効化。大量リクエスト/失敗ループ/予定外のWebhook流量にはCircuit breakerを用意。

## データ配置

開発中はローカルmock。実データ接続時は秘密キーをOSの安全な保管場所/秘密マネージャへ。クラウド移行時は通知、バックアップ、ドメイン、運用責任を確認。ユーザーがオフラインでもWebhookを受けたい場合はPC常時起動ではなく、クラウドworkerへの移行が必要。
