# ADR 0004: プラガブルな音声プロバイダー抽象化とモック先行アーキテクチャ

## ステータス
Accepted (CR-001設計変更)

## コンテキスト
音声対話機能は JARVIS Business OS の重要なインターフェース候補であるが、現在検討されている候補技術はユースケースと性質が大きく異なる：
1. **OpenAI GPT-Live (`gpt-live-1`)**: 双方向の自然な全二重会話、発話割り込み、JARVIS COREなど別バックエンドへの委譲（client delegation）を評価する候補。
2. **Google Gemini 3.8 Flash TTS (`gemini-3.8-flash-tts`)**: 確定した朝のブリーフィングや通知を高品質かつ好みの声質・話速で読み上げるテキスト→音声専用モデル。これ単体では会話対話を提供しない。
3. **Google Gemini 3.8 Live (`gemini-3.8-live`)**: リアルタイム対話の比較検証候補。

また、以下の安全・運用規律を遵守する必要がある：
- **ゼロ課金前提の先行検証**: 開発環境（Antigravity/Codex）の利用枠と自作アプリのAPI課金は完全に別である。ユーザーによる事前見積もりと個別予算承認がない限り、外部有料APIの呼び出しは一切禁止。
- **セキュリティ・権限境界**: 音声の「はい」「実行して」等の発話だけで高リスク操作（発注、送金、データ削除、設定変更）を承認してはならず、認証済みUIでの個別確認を必須とする。
- **アクセシビリティ**: 音声オフやマイク不許可時でも、字幕とテキストUIにより100%同等の業務情報が取得できること。

## 決定事項
1. **プロバイダー抽象化の確立**:
   - `VoiceProvider` インターフェースを定義し、能力メタデータ（`VoiceCapabilities`: `realtimeDuplex`, `interruption`, `voiceCustomization`, `structuredTranscript`）を公開。
   - `VoiceSessionController` が状態遷移（`IDLE`, `LISTENING`, `DELEGATING`, `SPEAKING` など）、字幕、マイク許可、ミュート、UIイベント通知を統括。
2. **モックアダプター（`MockVoiceAdapter`）の先行実装**:
   - 初期M0/M1では、外部課金ゼロで動作する `MockVoiceAdapter` を実装。
   - 代表的な模擬対話（朝ブリーフ要約、割り込み、承認案内、エラー復旧）をシミュレーションし、R3Fコア状態や字幕DOMと連動させる。
3. **実プロバイダー接続の評価ゲート**:
   - 将来の接続アダプター（`OpenAIGptLiveAdapter`, `GeminiTtsChainAdapter`, `GeminiLiveAdapter`）は型定義と骨格のみを準備し、実際のAPIキー配置・課金通信はユーザー承認後に別タスクとして実施。
4. **決定論的ポリシーエンジンとの分離**:
   - 音声アダプターが業務データベースや外部ツールを直接操作することは禁止。すべての意図は JARVIS CORE とポリシーエンジンを経由する。

## 結果・影響
- 期待する影響: 将来の比較・差し替えを容易にする。現段階の実プロバイダー切替は拒否し、外部API接続を持たないモックだけで試験する。
- 負の影響/トレードオフ: 初期フェーズでは本物の音声モデルによるAI会話は体験できず、決定論的な模擬シーケンスによるUI/状態検証となる。
